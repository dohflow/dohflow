# ADR 0073 — Sync disposition rules

- **Status:** Accepted
- **Tier:** Public
- **Date:** 2026-09-20
- **Bead:** `personal-cfo-vlfd`
- **Decider:** Owner, program plan v0.8.1 §9.4 (recorded in the bead before
  implementation)
- **Builds on:** [ADR 0074](0074-dohflow-sync-architecture.md) (compare-and-
  swap and rollback-then-replay), ADR 0027 (additive balance assertions), and
  ADR 0055 (scenario reversal handles)
- **Consumers:** `personal-cfo-egn67` (SYNC-2b), `personal-cfo-0g528`
  (SYNC-2c), `personal-cfo-mpep3` (S3-2), and the two-vault simulator in
  `personal-cfo-tp2ln`

## Context

ADR 0074 makes the server head a compare-and-swap sequence and rebases an
outbox by rolling a scratch vault back to the base image, applying the pulled
tail, and replaying local envelopes whose write sets remain safe. A ledger
mutation cannot use last-write-wins: an apparently disjoint edit can still
violate a posting, reference, or forecast invariant. The rebase therefore
needs a deterministic, per-command rule that says whether an envelope is safe
to apply, needs a human choice, or must be reopened in an editor.

The current command bus already carries the provenance needed to keep a
disposition explainable. `CommandMeta` has the immutable `command_id`, the
logical `correlation_id`, and optional `causation_id` at
`crates/db-worker/src/lib.rs:174-188` (the plan's older
`finance-kernel/lib.rs:176` pointer is now the propagation site, such as
`finance-kernel/src/lib.rs:2503-2505`). A queued child that references a row
created by a queued parent must not be detached from that causal group.

The current `WriteCommand` enum has 49 variants at
`crates/db-worker/src/lib.rs:223-698`. Their doc comments are the source for
the four shapes below. The three hard-delete implementations are explicit
`DELETE FROM` statements in `apply/recurring.rs`:

- `recurring_transfers` at `:93-108`,
- `income_sources` at `:264-278`, and
- `bill_contracts` plus `recurring_events` at `:633-654`.

Those deletes cannot safely resolve against a concurrent edit. SYNC-2b must
tombstone them before the S1 command stream freezes. The five import commands
carry device-local staging references; SYNC-2c must reshape them before they
can be envelopes. `SkipStaged` is a local inbox action and never ships.

## Decision

### 1. Three outcomes and one rule

There are exactly three user-visible dispositions. No financial data is
silently dropped; an idempotent no-op is an **auto** disposition, not a drop.

1. **Auto.** Reapply the envelope on the new base when its write set is
   untouched and the command still validates. Equal end states and explicitly
   idempotent commands are safe no-ops.
2. **Queue-choose.** Preserve both the local envelope and the current-base
   value. The user chooses which scalar or toggle outcome wins; the choice is
   emitted as a new command and the queued command remains audit evidence.
3. **Queue-edit.** Open the existing editor with the envelope's intent
   prefilled. The user repairs a reference or invariant (split sum, category
   cycle, or asset/liability link) on the new base, then submits a new command.

The rule is **auto iff** both predicates hold:

```text
write_set_untouched_since(base_seq)
&& validates_against(the_new_base)
```

If either predicate is false, the whole `correlation_id` group queues. A
causal descendant (`causation_id`) that refers to an entity created by the
queued command queues with it, even if its row-level write set looks
disjoint. A group is never partially applied, silently merged, or discarded.

### 2. The four command shapes

The exhaustive 49-row appendix is generated by
`crates/db-worker/tests/adr_0073_disposition.rs`. The test parses the
`WriteCommand` declaration, requires exactly one mapping per variant, asserts
the shape counts (8 Create, 17 Set, 12 Toggle, 4 Base-dependent), and prints
the table used below. A new variant without a row fails the test before a
SYNC-2 implementation can ship it.

#### Create (8)

Create commands append an entity or balanced posting. They auto-apply when
all referenced rows are still valid on the new base. An invalid or deleted
reference opens **queue-edit**; the editor validates the repaired command
before it can be submitted. Postings append rather than overwrite another
device's money movement, so valid Creates commute.

#### Set (17)

The thirteen scalar Sets (`SetCardStatementBalance` included) default to
**queue-choose** when a concurrent value differs; an exact no-op is auto. The
three structural Sets are **queue-edit**:

- `SetSplits` must preserve the transaction sum invariant;
- `MoveCategory` must preserve the category no-cycle invariant; and
- `SetAccountLink` must preserve the real-asset → liability rule.

`SetTags` is **auto**: tags merge by set union and never remove another
device's tag. A balance assertion is still a Set, but it is never LWW: two
assertions for the same account and date always produce **queue-choose** with
both values and dates (ADR 0027; ADR 0074 Decision 5).

#### Toggle (12)

Archive/reinstate, void, unconfirm, snooze, and dismiss commands compare their
end state. Equal end states auto-apply; opposed states produce
**queue-choose**. The three hard deletes are not Toggle until SYNC-2b replaces
them with tombstones; their exception rows are listed separately below.

#### Base-dependent (4)

These commands must be re-evaluated against the new base rather than treated
as ordinary scalar Sets:

- `ConfirmObligationEarly` is **auto** after idempotent re-evaluation of
  `(recurring_event_id, scheduled_date)`; it must not post the same occurrence
  twice.
- `ConvertUnexplainedToTransaction` is **auto** after re-reading the latest
  assertion and residual plug. If the residual is gone or the account/reference
  is invalid, the normal validation/queue path applies; it never invents a
  replacement amount.
- `ApplyScenario` and `RevertScenarioApply` are **queue-choose**. The
  `command_id` is ADR 0055's reversal handle and survives rebase, so a
  resolver can choose the competing scenario state without losing the inverse.

### 3. Exceptions before the stream

These rows are deliberately not ordinary shape outcomes:

1. **Tombstone first (3).** `DeleteRecurringTransfer`, `DeleteIncomeSource`,
   and `DeleteRecurringBill` become soft deletes in SYNC-2b. Once tombstoned,
   each has an archive/reinstate Toggle disposition. No purge or compaction
   path may erase the tombstone while an envelope can reference it.
2. **Reshape first (4).** `CreateSourceBatch`, `AttachSourceRecord`,
   `UpdateBatchState`, and `CommitStaged` reference device-local staging.
   SYNC-2c materializes the command into class-1 or class-1b artifact data
   before it can enter an envelope; a replica never looks up an origin
   `staged_*` row.
3. **Never ships (1).** `SkipStaged` only changes a local staging/inbox
   decision. The envelope builder rejects it.
4. **Invalid references.** A valid Create is auto, but a missing account,
   category, recurring event, or other referenced row is the generic
   queue-edit path. It is not a silent no-op.
5. **Balance assertions.** They are replicated class-1 intent but never
   last-write-wins; the two-value/date choice is mandatory even if the rows
   otherwise look disjoint.

The generated appendix reports the rough planning tally from these paths:
23 default-auto rows, 15 scalar/Scenario queue-choose rows, 3 structural
queue-edit rows plus the generic invalid-reference Create queue-edit path, 3
tombstone-first rows, 4 reshape-first rows, and 1 never-ships row. The
planning shorthand “about 23 / 14 / 4” counts the grouped scenario and
generic-reference paths rather than treating every conditional branch as a
separate row; the test output is authoritative.

### 4. Correlation-group queueing and audit

The rebase executor evaluates the envelope's complete original metadata. If a
command queues, every causal descendant in the same `correlation_id` queues;
the queue record preserves the original envelope, its command/causation IDs,
and the reason. The replica's append-only operation-log row records
`applied_base_seq` and `rebased_from` (R46). Rebase never reuses a numeric
`op_seq`, never applies a command twice, and never installs a dispatchable
idempotency memo for a queued command.

Every enrolled device surfaces the queued group's age and origin device, and
shows a nag at 24 hours (R45). A group remains visible until the user resolves
it with a new command, or explicitly re-bootstraps; there is no expiry that
could look like a drop.

The two-vault simulator must cover these interleavings:

1. pull-first with an untouched valid envelope (auto);
2. seed-twin bootstrap (replicas never seed; genesis carries seed rows);
3. a queued correlation group visible, with age, on the other device; and
4. a rebase whose audit row records `applied_base_seq` / `rebased_from`.

The exit test is property-based: it generates two devices, random command
streams, and random push interleavings. Canonically ordered class-1 and class-2
rows must converge hash-equal; every non-auto envelope remains queued with its
group, no envelope is lost or applied twice, and connector ingestion cannot
commit past device-local staging without the outbox.

## Consequences

- SYNC-2b owns tombstones before any hard delete can be serialized.
- SYNC-2c owns import materialization and the payload-reference lint; it must
  reject a staging ID or local attachment identity in an envelope.
- SYNC-2 and SYNC-1c use the same auto-iff predicate and correlation closure;
  neither may add a per-table LWW exception.
- S3-2 renders queue-choose as a side-by-side scalar/toggle choice and
  queue-edit using the existing split, category, liability-link, or create
  editors. It shows groups, age, origin, and the R46 audit fields—not isolated
  envelopes.
- The implementation changes no current runtime, schema, or user-visible
  behavior. Until those downstream beads land, this ADR is the binding
  protocol contract for the future Sync stream.

## Rejected alternatives

- **Last-write-wins for ledger mutations.** It can overwrite a valid posting or
  violate a cross-row invariant while appearing conflict-free.
- **Row-level CRDTs.** Ledger intent is not a commutative register; balance,
  split, and reference invariants need domain-aware resolution.
- **Field-level merge for money-moving commands.** Merging fields can create a
  posting combination no user issued and cannot preserve the command's
  provenance.
- **A lease or takeover path.** Offline work must remain possible; lease
  expiry creates a second-writer window and a new recovery UX.
- **Drop as an outcome.** An idempotent no-op is the only automatic absence of
  mutation; financial data is never silently discarded.

## Revisit if

- A new `WriteCommand` shape appears; the exhaustive `#[test]` forces a row
  and a reviewed disposition before it can ship.
- The queue-edit UI proves unusable in dogfood (S3), requiring a new ADR rather
  than an implicit fallback to LWW.
- ADR 0027's balance-assertion semantics change.
