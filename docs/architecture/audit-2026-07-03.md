## 2. Codebase hardening audit

Sixty-plus findings, filed as epic **`personal-cfo-3fdd`** with 17 children. The high-order
themes:

### Will bite soon (P2)
| Bead | Finding |
|---|---|
| `3fdd.1` | **Transaction list hard-capped at 200 rows** (`TRANSACTION_LIST_LIMIT`) — search, facet filters, and the ⌘K palette silently operate on the newest 200 only. Server-side filter/sort/pagination is the fix; the most user-visible scale wall in the app. |
| `3fdd.2` | **db-worker monolith**: `lib.rs` is 16.6k lines (1.8k-line, 69-arm `apply_command`; 10k-line in-file test module); `forecast.rs` 2.7k lines. Pure-move decomposition. |
| `3fdd.3` | **Read-path N+1s**: correlated subqueries per transaction row, a missing `balance_observations` index, and per-account assertion queries in the cash-tier rollup. |
| `3fdd.4` | **Op-log provenance**: the `entity_table` match falls through `_ => "accounts"` — new commands silently mislabel their audit rows. Make it exhaustive. |
| `3fdd.5` | **Idempotency is theater today**: blank keys mint fresh UUIDs, so a retried action double-posts instead of replaying. Frontend must mint stable per-action keys. |
| `3fdd.6` | **No Tauri v2 command capabilities**: a compromised renderer can invoke `delete_vault`/`export_backup`. Scope destructive commands. |

### Scheduled refactors (P3)
Incremental projections (`3fdd.7` — commitments rebuilds fully inside every bill write;
money-inbox likewise), unlock-path responsiveness (`3fdd.8` — persist→actualize→backtest
block unlock), the frontend invalidation registry (`3fdd.9` — ~100 hand-listed key sets, one
already drifted), drawer context (`3fdd.10`), shared importer math (`3fdd.11` — three
divergent copies of fingerprint-critical parsing), revolving overflow discipline (`3fdd.12`),
the forecast collector seam (`3fdd.13` — the aggregate/per-account parity gap already bit
once), IPC ergonomics (`3fdd.14` — 5 touch points per command), crypto hardening tests
(`3fdd.15` — nonce uniqueness, KDF floor, manifest schema versioning, migration schema-hash),
and forecast source pruning (`3fdd.16`).

### Deferred (P4)
URL-driven navigation (`3fdd.17`) — quality-of-life, revisit after the hardening lands.

### What the audit did NOT find
No exploitable security defect, no data-integrity hole in the shipped paths, and no
correctness bug in the money math. The security lens verified DEK zeroization, lock ordering,
envelope crypto, and the state machine as sound. The findings are about *durability under
growth* — data volume, contributor count, and feature velocity — which is exactly where a
pre-OSS-launch codebase should be investing.

## 3. Method note
Both audits ran as parallel read-only agent lenses with code-cited findings, followed by
verification and one-at-a-time application of graph changes. Agent claims were spot-checked
before acting; several recommendations were rejected (e.g. "close blocked beads" — blocked is
not stale; "close future schema beads" — valid backlog), and the shipped-pending-merge beads
(`fr79`, `z5lj`, `yequ`) were left open for the post-merge close per convention.
