### Items inside `core:default` checked individually

- **No window/webview creation or navigation.** `core:webview|create_webview_window`,
  `core:window|create` and every URL-setting command are absent from the
  expansion, so main-window JavaScript cannot open a new window or point a
  webview anywhere [gen].
- **`core:image|from_path`** would load an image file from a path. The command
  is compiled to a stub that returns an error unless `tauri` has the
  `image-png` or `image-ico` feature (`tauri-2.11.2/src/image/plugin.rs`), and
  neither is enabled [src]. Inert.
- **`core:tray|*`** is granted, but the tray plugin is registered only with the
  `tray-icon` feature (`tauri-2.11.2/src/app.rs`), which is not enabled [src].
  Inert.
- **`core:webview|internal_toggle_devtools`** calls `open_devtools`, which is
  compiled only with `debug_assertions` or the `devtools` feature
  (`tauri-2.11.2/src/webview/mod.rs`) [src]. Inert in release (§5).
- **`core:menu|*`** is registered on desktop. It only affects the trusted
  window's own menus. Accepted under the `core:default` baseline.
- **`core:event|emit_to`** lets `main` emit to other windows. The shells cannot
  `listen` (their capability is empty), so nothing is received [gen][test].

## 4. Controls verified

### 4.1 Deny-by-default app ACL

`permissions/` exists, so `tauri-build` registers the app ACL manifest and
`Webview::on_message` rejects any command no capability grants to the calling
window — app commands, plugin commands and `core:*` alike
(`tauri-2.11.2/src/webview/mod.rs`) [src]. Every registered command is in
exactly one permission set [test], and the drift audit names any gap
(`acl-coverage`) [test].

### 4.2 No untrusted financial or destructive IPC

On Tauri's mock runtime, with the ACL resolved from the committed files,
`document_preview` and `agent_report` are rejected for `vault_status`,
`delete_vault`, `plugin:event|listen`, `plugin:window|set_theme`,
`plugin:webview|create_webview_window`, `plugin:dialog|save`,
`plugin:opener|open_url`, `plugin:updater|check` and `plugin:process|restart`,
while `main` is allowed the general and destructive surfaces [test]. The
windows are built by the app's own `windows` module, not by the test. The
destructive set reaches only `main`; that is a code invariant checked against
both the configuration and the baseline (`destructive-reach`) [test].

**The one ACL exception.** `plugin:__TAURI_CHANNEL__|fetch` skips the ACL, and
its queue is app-wide under sequential ids
(`tauri-2.11.2/src/ipc/channel.rs`) [src]. It only matters if app code sends
large `tauri::ipc::Channel` payloads. The app defines no `ipc::Channel`
(addendum 2026-09-27, rule 7), and a source test enforces that [test].

### 4.3 No arbitrary remote WebView navigation

- **Navigation guard.** It is a plugin, so it applies to every webview. It
  cancels any navigation outside the bundled origin: `tauri://localhost`, or
  `http(s)://tauri.localhost` on Windows/Android only, never with a port. The
  dev server is allowed only when `tauri::is_dev()` [src][test]. Blocked
  attempts log scheme and host only [src]. Each untrusted label was driven
  through the guard [test].
- **New windows.** Both builders install `on_new_window(… Deny)`, so
  `window.open` / `target="_blank"` cannot create a webview or popup on any
  platform [src][test].
- **No remote content.** No window URL points at a remote origin, and no
  capability declares `remote` [test].
- **External links go to the system browser.** `open_url` checks a glob
  against the raw URL string. The literal prefix `https://dohflow.app/` pins
  the host, and an entry without `app` refuses any `with`
  program (`tauri-plugin-opener-2.5.5/src/scope.rs`) [src]. The opener's
  anchor-click interceptor is off, so `openExternal.ts` is the only path to
  it [src][test].

### 4.4 CSP: accepted style exception versus prohibited script relaxations

**Configured production policy** (`app.security.csp`) [src][test]:

```
default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline';
connect-src 'self' ipc: http://ipc.localhost; img-src 'self' data:;
font-src 'self'; object-src 'none'; frame-src 'none'; base-uri 'self';
form-action 'none'
```

**Effective production policy.** Tauri rewrites the configured policy per asset
(`tauri-2.11.2/src/manager/mod.rs` `set_csp`; `tauri-codegen-2.6.2`,
`tauri-utils-2.9.2/src/html.rs`) [src]:

- **`script-src`** gains a `'sha256-…'` hash for each bundled `.js` file. The
  built `dist/` holds one module script and no inline script, so the effective
  directive is `'self'` plus that hash. No `'unsafe-inline'`, no
  `'unsafe-eval'`.
- **`style-src`** would gain a nonce only for a `<style>` element in the HTML.
  The built `dist/index.html` and `dist/isolated-shell.html` contain none, so
  `style-src` stays exactly `'self' 'unsafe-inline'`. This matters: under CSP
  rules a nonce or hash in `style-src` would make browsers **ignore**
  `'unsafe-inline'`. The runtime inline `style` attributes that Radix and
  Tailwind rely on therefore keep working, as the exception intends.

The two kinds of `unsafe-inline` are separate decisions:

| | Status | Enforcement |
|---|---|---|
| `style-src 'unsafe-inline'` | **Accepted exception** (ADR 0010: style injection is not a code-execution vector; tightening to nonce/hash is a follow-up) | Recorded in the baseline; allowed only in `style-src` by code invariant |
| `'unsafe-inline'` / `'unsafe-eval'` / `'wasm-unsafe-eval'` in `script-src` | **Prohibited** in production | `csp-invariant`: `script-src` must be exactly `'self'`, checked against configuration **and** baseline [test] |
| Remote or wildcard sources in any directive | **Prohibited** | `csp-egress`: only `ipc:` / `http://ipc.localhost` in `connect-src` and `data:` in `img-src` (plus the dev server in development) [test] |

The frontend has no `eval`, `new Function`, `dangerouslySetInnerHTML`,
`window.location`/`location.href` assignment or `window.open` call; this was
re-checked at this SHA [src]. `index.html` loads `theme-boot.ts` as a module,
not an inline script [src].

### 4.6 Scoped opener and updater grants preserved

- **Opener.** Exactly one `opener:*` entry across all capabilities:
  `opener:allow-open-url`, scope `{url: "https://dohflow.app/*"}`, no deny
  list, in `default.json` [test][gen]. Not granted: `opener:default`,
  `allow-default-urls`, `allow-open-path` or `allow-reveal-item-in-dir` [test].
- **Updater.** `updater:default` only, in `default.json`. There is one pinned
  endpoint (`https://github.com/dohflow/dohflow/releases/latest/download/latest.json`)
  and a committed minisign public key [test]. The plugin verifies the
  signature over the downloaded bytes before install (`verify_signature` in
  `tauri-plugin-updater-2.11.0/src/updater.rs`), and the config does not set
  `dangerousInsecureTransportProtocol` [src]. The fetch happens in Rust, so the
  CSP gains no GitHub origin [src][test].
- **Process.** `process:allow-restart` only, in `destructive.json`;
  `process:default` is absent [test].
- **Never granted anywhere:** `shell:*`, `fs:*`, `http:*` [test].

## 7. Residual risks

1. **The shells have never been probed in a real WebView.** Their isolation is
   proven on Tauri's mock runtime with the real ACL, through a headless launch
   that built all three windows on the real runtime (PR #39, at `3c9bcb7`),
   and from source. Nobody has yet run an `invoke`, navigation or `window.open`
   attempt from inside a real shell WebView, because screen control was not
   available to the implementation or review sessions. The shells are
   unreachable from the UI, so there is no user-facing exposure today. This
   gap has to close before `personal-cfo-vrng` / `-z6pn` make a shell
   reachable.
2. **Live evidence for `main` predates the current window construction.** The
   2rf reviewer's live smoke at `98bd4f3` observed a remote navigation blocked,
   dialogs, the opener and the update check. `main` has since moved to
   `windows::build_main` (PR #39). Its construction was re-verified headlessly,
   not interactively.
3. **`dynamic-acl` is on** (a Tauri default feature), so Rust code *could* call
   `Manager::add_capability` at run time and grant permissions outside the
   reviewed files and the drift audit. App code does not call it at this SHA
   [src]. No test forbids it (§8).
4. **Channel-fetch ACL exception** (§4.2): an upstream Tauri behavior, managed
   by not using `ipc::Channel`, not fixed.
5. **`core:default` breadth.** `main` receives menu, image and event commands
   it barely uses. This is accepted by ADR 0010 for the trusted window. The
   potentially sensitive ones (`image|from_path`, `tray`, devtools toggle) are
   inert in this build (§3). That inertness depends on Cargo features a future
   change could enable; the drift audit pins the `tauri` feature set.
6. **Windows and Android** origin and new-window behavior is covered by unit
   tests and source reading only. There is no Windows or Android build today.
7. **`style-src 'unsafe-inline'`** remains the accepted exception. Tightening it
   is an ADR 0010 follow-up, not a defect.
